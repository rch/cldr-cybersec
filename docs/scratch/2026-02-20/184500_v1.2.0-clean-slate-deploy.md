# Clean-Slate Zarf v1.2.0 Deployment under Disk Pressure

**Date**: 2026-02-20
**Node**: tinybox (64-core, 128GB RAM, Ubuntu 22.04, RKE2 v1.34.3+rke2r3)
**Package**: cybersec-dask-amd64-1.2.0.tar.zst (1.37 GB)
**Result**: PASS — all components deployed and verified at 94% disk utilization

## What's New in v1.2.0

| Fix | Impact |
|-----|--------|
| S3_BUCKET defaults to `cybersec-dask-data` | Consistent bucket name across all components |
| Auto S3 bucket creation on deploy | Users don't need to create bucket manually |
| JupyterHub NetworkPolicy fix | Notebooks can reach Dask scheduler and MinIO |
| S3_BUCKET in JupyterHub extraEnv | Notebooks inherit the correct bucket name |
| Split DaskCluster manifests (v1.1.1) | No more silent CRD creation failure |

**Bug found during test**: The bucket creation action used `###ZARF_VAR_*###` template
syntax in a `cmd` action, but Zarf only substitutes templates in manifest/values files.
In `cmd` actions, use `$ZARF_VAR_*` environment variables. Fixed in zarf.yaml for v1.2.1.

### Step 0: Set Up Environment

# alias kubectl="sudo kubectl"

### Step 1: Configure Kubelet Eviction Thresholds (Disk >85%)

**Skip this step if your system drive has >15% free.**

If your node is >85% full, the default kubelet eviction thresholds (5%) will
trigger DiskPressure, evicting pods. Configure higher tolerance:

```bash
sudo mkdir -p /etc/rancher/rke2
sudo tee /etc/rancher/rke2/config.yaml > /dev/null << 'YAML'
kubelet-arg:
  - "eviction-hard=nodefs.available<2%,imagefs.available<2%,memory.available<500Mi"
  - "eviction-soft=nodefs.available<5%,imagefs.available<5%,memory.available<1Gi"
  - "eviction-soft-grace-period=nodefs.available=2m,imagefs.available=2m,memory.available=2m"
  - "eviction-minimum-reclaim=nodefs.available=500Mi,imagefs.available=500Mi,memory.available=500Mi"
  - "image-gc-high-threshold=99"
  - "image-gc-low-threshold=98"
YAML

# IMPORTANT: image-gc-high-threshold=99 prevents containerd from garbage-collecting
# cached container images. Without this, air-gap deployments get ImagePullBackOff.

sudo systemctl restart rke2-server

# Wait for API server (usually <30 seconds)
until kubectl get nodes &>/dev/null; do sleep 5; done

# Wait for node Ready (may take up to 5 minutes due to evictionPressureTransitionPeriod)
kubectl wait --for=condition=Ready node --all --timeout=300s

# Clean up any pods evicted during restart
kubectl delete pods -A --field-selector=status.phase=Failed 2>/dev/null
```

### Step 2: Clean Up Failed Init (if applicable)

**Skip this step if you've never run `zarf init` on this cluster.**

If a previous `zarf init` failed and left a PVC in `Lost` phase (check with
`kubectl get pvc -n zarf`):

```bash
# Remove stuck PVC finalizer and force-delete
kubectl patch pvc zarf-docker-registry -n zarf -p '{"metadata":{"finalizers":null}}' 2>/dev/null
kubectl delete pvc zarf-docker-registry -n zarf --force --grace-period=0 2>/dev/null

# Remove orphaned PV
kubectl patch pv zarf-registry-pv -p '{"metadata":{"finalizers":null}}' 2>/dev/null
kubectl delete pv zarf-registry-pv --force --grace-period=0 2>/dev/null

# Remove zarf namespace if it exists
kubectl delete namespace zarf --wait=false 2>/dev/null

# Wait for cleanup
sleep 10

# Verify clean
kubectl get pvc -n zarf 2>&1     # Should say "not found"
kubectl get pv zarf-registry-pv 2>&1  # Should say "not found"
```

**DO NOT use `--set REGISTRY_PVC_ENABLED=false`** — this crashes the registry
with "no storage configuration provided".

### Step 3: Prepare Registry Storage

```bash
# Create directory on LOCAL disk (not NFS — registry needs hard links)
sudo mkdir -p /var/lib/zarf-registry
sudo chown 1000:2000 /var/lib/zarf-registry

# Pre-create 5Gi hostPath PV with claimRef
# The claimRef pre-binds this PV to the PVC that zarf init will create
kubectl apply -f - << 'EOF'
apiVersion: v1
kind: PersistentVolume
metadata:
  name: zarf-registry-pv
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  hostPath:
    path: /var/lib/zarf-registry
    type: DirectoryOrCreate
  claimRef:
    namespace: zarf
    name: zarf-docker-registry
EOF

# Verify
kubectl get pv zarf-registry-pv
# Expected: Available, 5Gi
```

## Troubleshooting

### PVC Stuck in Lost Phase

**Symptom**: `kubectl get pvc -n zarf` shows `Lost` status
**Cause**: Previous failed `zarf init` left orphaned PVC
**Fix**: See Step 2 above (patch finalizer → force delete → clean namespace)

### Registry Crashes with "no storage configuration provided"

**Symptom**: Registry pod CrashLoopBackOff
**Cause**: Used `--set REGISTRY_PVC_ENABLED=false`
**Fix**: NEVER disable PVC. Instead, pre-create a hostPath PV (Step 3) and use
`--set REGISTRY_PVC_SIZE=5Gi`

### ImagePullBackOff at High Disk Usage

**Symptom**: Pods stuck in ImagePullBackOff, `crictl images` shows missing images
**Cause**: containerd garbage-collected cached images (default threshold: 85%)
**Fix**: Set `image-gc-high-threshold=99` in `/etc/rancher/rke2/config.yaml` (Step 1)

### DiskPressure Won't Clear

**Symptom**: Node shows `DiskPressure=True` even after freeing disk
**Cause**: `evictionPressureTransitionPeriod` is 5 minutes by default
**Fix**: Wait 5 minutes after disk usage drops below the threshold

### Bucket Creation Failed During Deploy

**Symptom**: Warning about bucket creation in deploy output (non-fatal)
**Cause**: Template variable bug in v1.2.0 (fixed in v1.2.1)
**Fix**: Create manually:
```bash
kubectl exec -n dask deploy/cybersec-dask-scheduler -- python -c "
import s3fs, os
fs = s3fs.S3FileSystem(
    key=os.environ.get('AWS_ACCESS_KEY_ID', ''),
    secret=os.environ.get('AWS_SECRET_ACCESS_KEY', ''),
    client_kwargs={'endpoint_url': os.environ['S3_ENDPOINT']}
)
bucket = 'cybersec-dask-data'
try:
    fs.ls(bucket)
    print(f'Bucket exists: {bucket}')
except FileNotFoundError:
    fs.mkdir(bucket)
    print(f'Created: {bucket}')
"
```

### Stale Container Images (Upgrades Only)

**Symptom**: Pod runs old code despite new package deploy
**Cause**: containerd caches images with `imagePullPolicy: IfNotPresent`
**Fix**:
```bash
CRICTL="sudo /var/lib/rancher/rke2/bin/crictl -r unix:///run/k3s/containerd/containerd.sock"
$CRICTL images | grep cybersec-dask
$CRICTL rmi <image-id>
kubectl delete pod -n panel-viz -l app=otel-navigator
kubectl delete pod -n panel-viz -l app=navigator-engine
```
